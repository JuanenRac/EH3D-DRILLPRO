**正直さの確認 - 今日実際に動くもの：** 80x25 のテキストモードインターフェースを持つ Rust プログラムです。Excellon `.NCD` ドリルファイル、工具テーブル、機械設定を読み込み、穴を並べ替えて表示し、ジョブ全体を **シミュレーター上**（既定）で、または機械ファイルで指定すればパソコンのシリアルポート、USB シリアルアダプター、EH3D-NODE-BUNGARD 経由で **実機上** で実行します。パソコン上で 228 件のテストが動きます。実機の Bungard CCD MTC では、3 軸の原点出し（Z、X、Y をリミットスイッチまで動かし、制御ユニットの「3 軸すべて原点」信号をその場で確認）と各軸の動きを試しました。**ドリル加工ジョブ全体はまだ機械で実行していません**。1 ミリあたりのステップ数は、オリジナルの設定と照合しただけです。 既定では MS-DOS 版のクラシック画面（原版とセル単位で照合済み）が表示されます。`--modern` でメニュー式の画面を起動します。 キーボードとマウスで操作でき、ウィンドウは最大化できます（画面は 640x400 から 1080p 以上まで拡大縮小）。設定ファイルと工具表はダイアログで編集・保存でき、「情報」ボタンで Bungard CCD と CCD/2 の機種（MTC 対応、ATC は未対応）を確認できます。 コンソール版（`drillpro-console`）は同じ画面をターミナルに表示し、キーボードとマウスで操作でき、ウィンドウシステムは不要です（SSH、テキストコンソール、古い PC）。 各バージョンのパッケージには、1行ずつ解説した基本設定と、1穴から2万穴までの `examples` フォルダーが含まれます。ATC 機種（自動工具交換）の工具交換は元のプログラムの記録に基づいており、実機ではまだ動かしていません。

---

> **安全性とセキュリティの現状：** このプログラムは安全システムではありません。実機接続（機械ファイルの `connection`）では **開始で機械が動きます**。工具を外し、機械の電源スイッチに手を置き、ジョブを即座に止めてステッピングドライバをオフにする `Esc` をいつでも押せるようにしてください。リミットスイッチは機械自身の制御ユニットが監視します（スイッチで軸を自分で止めます）。このソフトウェアには独自の非常停止がなく、誤ったステップバイトや速度は、工具を加工物やテーブルにぶつけたり、モーターに脱調を起こしたりすることがあります。プロトコル層は、アーム（有効化）されるまで何も動かしません。このプロジェクトは独立しており、Bungard Elektronik が製造・推奨・サポートするものではありません。製品名は、対応するファイル形式と機械を示すためだけに使っています。

## 🎯 概要

* **ファイルリーダー**：Excellon の `.NCD` 穴あけファイル（`M48` ヘッダーの有無どちらも、モーダル座標、1 mil のインチ単位）、工具テーブル `DRILLPRO.DTD`、マシン設定 `DRILLPRO.DCF`。
* **ジョブプランナー**：穴を並べ替え（ファイル順、X 優先、Y 優先、最短経路）、工具ごとにまとめます。
* **画面**：CGA の色、メニュー、ファイルダイアログ、穴のベクター表示を備えた 80x25 のテキストモード画面を、ウィンドウに表示します。英語、スペイン語、イタリア語、ドイツ語、フランス語、ポルトガル語、中国語、日本語に対応し、言語はメニューか起動時の `--lang` で選びます。
* **マシンプロトコル**（`protocol/`、クレート `eh3d-drillpro-protocol`）：画面を持たないライブラリで、バイト転送（シリアルポートまたはシミュレーター）、加減速ランプ付きのミリメートル単位の動作計画、有効化されるまで動作を拒否する安全ゲートを含みます。
* **シミュレーター**：ハードウェアなしで作業全体を最後まで実行できます。テストもこれを使います。
* **対象機械**：DOS ソフトウェア 4.6 を使っていた、シリアルポート接続の制御ユニットを持つ機械。Bungard CCD MTC と CCD/2 MTC（手動工具交換。CCD/2 は小型の 325 x 270 mm テーブル）です。テーブルサイズなどの機械定数は機械の設定ファイルから取ります。試したのは CCD MTC のみで、スピンドルと集塵機の起動出力はまだ試していません。ATC の 2 モデル（CCD ATC と CCD/2 ATC、自動工具交換）は、リバースエンジニアリングで可能な範囲で、別のアプリケーションとして作ります。XL モデルとそれ以降の機械は、独自の最新制御ユニットとソフトウェアを備えており、対象外です。
* **機械ファイル**（`machine.cfg`、DRILLPRO と ROUTEPRO で共有）：ジョブが機械に届く方法（`demo` シミュレーター、`rs232` パソコン自身のシリアルポート、`usb` USB シリアルアダプター、`node` ネットワーク経由の EH3D-NODE-BUNGARD）と、1 行 1 値で、実機で調整したすべて（探索速度とランプ、校正ジャンプ、モーターの限界）を記します。
* **原点出し**：Z をリミットスイッチまで上げ、次に X と Y、最後にやわらかい校正ジャンプを行います。制御ユニットは RI ラインで「3 軸すべて原点」を知らせ、プログラムがそれを監視します。機械が原点に停止している場合は探索を省略し、X と Y をスイッチから 10 mm 離してから再度探索して、到着をその場で確認します。
* **安定した動き**：動きは、バイトの位置が時間を表す 1 本の連続ストリームとして送られます（そうしないと USB アダプターはバイトをまとめて届けます）。Z は 1 バイトずつ動かし、`Esc` はジョブを瞬時にキャンセルしてステッピングドライバをオフにします。
* **スピンドル**：既定では制御ユニット自身のもの（ラッチビット、最大 60000 rpm）。機械ファイルで `spindle = node` にすると、作業は代わりに EH3D-NODE-BUNGARD に頼みます（ノードの出力に付けたインバーター、ノードの最大までの任意の速度、停止のたびに停止）。ノードを使うと、プログラムは機械のランプも読むので、各軸が原点に着くのをストリームの途中で原点ラインを読まずにその場で確認できます。
* **サーバー接続**（機械ファイルで `connection = server`、`server_address`、`server_token`、`server_machine` を指定）：プログラムは自分で機械を動かす代わりに、作業を [EH3D-SERVER](https://github.com/JuanenRac/EH3D-SERVER) に送ります。サーバーが機械の定数で計画し、機械のノード経由で実行し、進み具合をプログラムに伝えます。プログラムはこれまでどおり進捗を表示してダイアログに答え、`Esc` でサーバー上の作業を停止します。プログラムを閉じても作業は止まりません。
* **作業アーカイブ、Offset ウィンドウ、シミュレーション**：作業は ZIP アーカイブにまとめられます（Select File ウィンドウがその中に入り、`drillpro JOB.ZIP` は最初の穴あけファイルを読み込みます）。ファイル名の横の矢印は `*.NCD`、`*.ZIP`、`*.*` のパターンを一覧にします。工具ウィンドウと設定ウィンドウの Load ボタンは読み込むファイルを選びます。実機では Offset ウィンドウが原点復帰を行い、ウィンドウの動きすべてに追従し、再び原点復帰します。シミュレーションは実機と同じ時間をかけて進みます。
* **サウンド**：マシンファイルの `sound_finish` と `sound_tool_change` は、それぞれ off（既定）、`default`（プログラムが出す音）、または自分の WAV ファイルのパスです。前者はジョブが自然に終わったとき、後者はマシンがツールを求めたときに鳴ります。
* **複数のマシンとステーション**：`connection = server` のとき、`drillpro --machines` はサーバーのすべてのマシンをステーション別に、各マシンの状態、ジョブ、準備済みジョブとともに一覧します（サーバーは全マシンについて一度に答えます）。`drillpro --machine ID` は、このプログラムのジョブをマシンファイルのマシンではなくそのマシンに送ります。マシンは同時に動き、各マシンに 1 つのジョブが走ります。
* **設定ウィンドウで選ぶ接続：** ジョブがマシンに届く 5 つの方法（シミュレーター、シリアルポート、USB アダプター、EH3D ノード、EH3D サーバー）のドロップダウンと、その下に各方法で必要なもの（ポート、アドレスとトークン、サーバーのマシン）を表示します。選んだ内容は確認され、OK で適用され、マシンファイルのほかの行に触れずに書き込まれます。
* **点滅するカーソル：** 編集中の数値・テキスト欄のカーソルが点滅します（0.5 秒点灯、0.5 秒消灯）。倣っている画面と同じです。
* **切り残し付きパネルと続行できるジョブ：** パネルの外側に切り残し（数、幅、位置）を付けられ、ジョブは完了済みの穴を除いて停止後に続行できます。ウィンドウは最大化で開きます。

### 🆚 オリジナルとこのバージョン

オリジナルは Bungard の CCD マシンを制御するクローズドな MS-DOS プログラムです。このバージョンは、オリジナルの動作の記録（画面、ファイル、制御ユニットへ送る内容）をもとに書き直したもので、オリジナルのコードは含みません。同じところと違うところ：

| 項目 | オリジナル (MS-DOS) | このバージョン |
|---|---|---|
| コンピューター | MS-DOS の PC（またはエミュレーター）のみ | Windows、Linux、macOS（32/64 ビット）。SSH や古い PC 向けのコンソール版もあり |
| 画面 | 80x25 テキストモード | 既定では同じクラシック画面（オリジナルとセル単位で照合済み）で、マウスに対応し、ウィンドウは 640x400 から 1080p 以上まで拡大縮小します。`--modern` はメニュー式、EH3D-BUNGARD-GUI はグラフィカルな画面です |
| 言語 | プログラム固有の言語 | 8 言語：英語、スペイン語、イタリア語、ドイツ語、フランス語、ポルトガル語、中国語、日本語。メニューまたは `--lang` で切り替え |
| パネル | テーブル上に基板をコピー | テーブル上に基板をコピー。途中で止まったジョブは次の穴から再開できます |
| マシンとの接続 | コンピューターのシリアルポートから制御ユニットへ | 既定ではシミュレーター。実機ではシリアルポート、USB シリアルアダプター、ネットワーク経由の EH3D-NODE-BUNGARD、または EH3D-SERVER を Config ウィンドウのドロップダウンで選択 |
| 追加 | いずれもなし | ジョブ全体を実行できるシミュレーター、ジョブ終了と工具要求の音、サーバー経由の複数マシン同時運用、ZIP ジョブアーカイブ、DXF と Gerber の外形、点滅カーソル、変更のたびに実行されるテスト |
| ソースとライセンス | クローズド、プロプライエタリ | オープンソース（GPL-3.0-or-later）、Rust 製 |
| 成熟度 | 実機で長年の使用実績 | ずっと新しい：基準点復帰と各軸の動作は実機の Bungard CCD MTC で試しましたが、ジョブ全体はまだ実機で動かしておらず、ATC モデルの工具交換も実機では未確認です |

## 🧩 EH3D での役割

EH3D-DRILLPRO は、制御ユニットがすべてのモーターステップを PC に生成させるマシン向けの、EH3D ファミリーの単独プログラムです。フライス加工向けの姉妹プロジェクト EH3D-ROUTEPRO は、そのプロトコル、画面、言語対応を再利用します。ZIP アーカイブにまとめた作業には EH3D-COMMON のクレート（`eh3d-archive`）を使うため、ビルドには隣のフォルダーに置く必要があります。将来は EH3D-CORE-LIBS の Excellon リーダーで置き換える可能性があります。 マシンのファイル（穴あけファイル、HP-GL ファイル、工具テーブル、マシン設定）は EH3D-COMMON のクレート `eh3d-bungard-formats` から来るため、これも隣のフォルダーに置く必要があります。

## 🚀 クイックスタート

安定版の Rust ツールチェーンが必要です。

```bash
cargo build --release --features gui
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
python -I tools/ci_validate.py
```

`run.bat`（Windows）または `./run.sh`（Linux と macOS）で実行します。どちらも必要ならプログラムを先にビルドします：`run.bat [FILE.NCD] [--lang en|es|it|de|fr|pt|zh|ja] [--data DIR] [--dump]`。`--data` は `DRILLPRO.DTD` と `DRILLPRO.DCF` があるフォルダー（既定：`testdata/`）、`--dump` は画面をプレーンテキストで出力します。キー：`Alt` とハイライトされた文字でメニューを開き、矢印で移動、`Enter` で決定、`Esc` で戻ります。メニューバーはクリックもできます。中国語と日本語にはシステムフォントに CJK フォントが必要です。 `--connection FILE` で既定とは別の機械ファイルを指定できます（既定は Windows では `%APPDATA%\EH3D\machine.cfg`、その他では `~/.config/eh3d/machine.cfg`）。機械ファイルがなければプログラムはシミュレーターで動きます。 `--modern` でクラシック画面の代わりにメニュー式の画面を起動します。

## 🧪 テスト

テストスイートは 228 件のテストから成ります（`cargo test --workspace`）。ファイル形式（ドリルファイル、ツールテーブル、マシンファイルと、その書き戻し）、作業計画、シミュレーター上のプロトコル（バイト、動作、原点復帰、ラッチビット、ノードとの接続、アームされるまで動かさない安全ゲート）、従来の画面のセル単位の照合、8 言語すべての画面を検証します。CI では `cargo fmt --check` と、警告をエラーとする `cargo clippy` も実行し、`python -I tools/ci_validate.py` がマニフェスト、バージョン、変更履歴、8 つの README を検査します。

**ビルド済みパッケージ:** 公開される各バージョンには、Windows（zip）、Linux（tar.gz）、macOS（Apple シリコンと Intel、tar.gz）用のパッケージが含まれ、プログラム、ライセンス、この README が入っており、それぞれ隣に SHA-256 が付きます。このリポジトリの `Release binaries` ワークフローでビルドされます。Releases ページからダウンロードしてください。Linux ではウィンドウに X11 または Wayland が必要です。

## 🗺️ ロードマップと既知の制限

**現時点で分かっている制限**

* 実機でのドリル作業全体はまだ実行されていません。1 台の Bungard CCD MTC で試したのは 3 軸の原点復帰と各軸の動作だけで、ミリあたりのステップ数は元の設定と照合しただけ、スピンドルと集塵機の出力は未試験です。
* `docs/PROTOCOL.md` には仮説のままの部分がまだ載っています。プロトコル層は、アーム（有効化）されるまで何も動かしません。
* ファイルリーダーは、テスト用に書いた小さなサンプルファイルでしか試しておらず、実際の基板のファイルでは試していません。
* サーバー接続（`connection = server`）はシミュレーターに対してしか試していません。
* 対応しているのは MTC モデルだけです。ATC モデルは未対応、XL モデルは対象外です。中国語と日本語にはシステムフォントに CJK フォントが必要です。

**次のステップ**

* 機械でドリル作業全体を実行し、ミリあたりのステップ数、スピンドル、集塵機の出力を確認する。
* 実際の基板のファイルでファイルリーダーを試す。
* リバースエンジニアリングで可能な範囲で、ATC モデル向けの別アプリケーションを作る。
* [EH3D-CORE-LIBS](https://github.com/JuanenRac/EH3D-CORE-LIBS) の Excellon リーダーが整ったら、独自のリーダーをそれに置き換える。
